# Мини-система бронирования

Учебный проект: подключение к PostgreSQL на Python с помощью `psycopg2`,
модуль-драйвер `db_driver` с готовыми CRUD-методами, модели данных и
графический интерфейс на `tkinter`.

## Состав проекта

| Файл | Назначение |
|---|---|
| `db_driver.py` | Модуль-драйвер: класс `Database` с CRUD-методами |
| `models/` | Dataclass-модели `User`, `Table`, `Booking` |
| `backend.py` | CRUD-функции над моделями и служебные операции |
| `create_tables.py` | Создание таблиц `users`, `tables`, `bookings` |
| `gui/` | Графический интерфейс на tkinter (вкладки) |
| `main.py` | Точка входа — запускает графический интерфейс |
| `.env.example` | Шаблон параметров подключения (скопируйте в `.env`) |
| `requirements.txt` | Зависимости проекта |

## Требования

- Python 3.10+
- Запущенный сервер PostgreSQL

## Установка

1. Создайте и активируйте виртуальное окружение:

   ```powershell
   python -m venv .venv
   .venv\Scripts\Activate.ps1
   ```

2. Установите зависимости:

   ```powershell
   pip install -r requirements.txt
   ```

3. Создайте файл `.env` из шаблона и укажите свои параметры подключения:

   ```powershell
   Copy-Item .env.example .env
   ```

   Содержимое `.env`:

   ```
   PGHOST=localhost
   PGPORT=5432
   PGDATABASE=postgres
   PGUSER=postgres
   PGPASSWORD=your_password
   ```

## Запуск

`main.py` запускает графический интерфейс на tkinter:

```powershell
python main.py
```

Запуск через интерпретатор из `.venv` без активации окружения:

```powershell
.venv\Scripts\python.exe main.py
```

Перед первым запуском создайте схему базы данных — это можно сделать кнопкой
**«Создать таблицы»** на вкладке «Сервис» или из командной строки:

```powershell
python create_tables.py
```

## Графический интерфейс

Приложение состоит из четырёх вкладок:

| Вкладка | Назначение |
|---|---|
| «Пользователи» | CRUD над таблицей `users` |
| «Столы» | CRUD над таблицей `tables` |
| «Брони» | CRUD над таблицей `bookings` |
| «Сервис» | Создание таблиц, тестовые данные, очистка |

### Работа с записями

На каждой вкладке слева расположена таблица записей, справа — форма. Выберите
строку в таблице, чтобы заполнить форму, затем используйте кнопки:

- **Создать** — добавить запись по данным формы;
- **Сохранить** — обновить выбранную запись;
- **Удалить** — удалить выбранную запись (с подтверждением);
- **Очистить форму** — сбросить поля формы.

Поля с внешними ключами (пользователь и стол во вкладке «Брони») выбираются из
выпадающих списков, дата и время вводятся в формате `ГГГГ-ММ-ДД` и `ЧЧ:ММ`.
Ошибки базы данных и некорректный ввод показываются во всплывающих окнах.

### Проверка доступности стола

Во вкладке «Брони» есть кнопка **«Проверить доступность»** — она вызывает
функцию `check_table_availability` и сообщает, свободен ли выбранный стол
в указанные дату и время.

Пересекающиеся брони одного стола запрещены: `create_booking` и
`update_booking` перед записью проверяют доступность и при конфликте
выбрасывают `BookingConflictError`. Правила проверки:

- интервалы считаются пересекающимися, если `начало < чужой_конец` и
  `чужое_начало < конец`;
- брони со статусом `cancelled` стол не занимают;
- при обновлении брони она сама исключается из проверки
  (параметр `exclude_booking_id`).

### Поиск и фильтры

- **Поиск** — подстрочный поиск без учёта регистра по текстовым полям уже
  загруженных строк.
- **Поиск по ID** — быстрая загрузка одной записи по её идентификатору.
- **Фильтры** — условия по конкретным полям, которые передаются в `where`;
  пустое поле фильтра не учитывается.
- **Сортировка** — выбор колонки и направления (`ASC`/`DESC`).
- **Лимит** и **Смещение** — постраничный вывод (`limit`/`offset`).
- Кнопки **«Применить»** и **«Сбросить»** управляют фильтрами.

### Вкладка «Сервис»

- **Создать таблицы** — инициализация схемы (`users`, `tables`, `bookings`);
- **Заполнить тестовыми данными** — добавление демонстрационных записей;
- **Очистить таблицы** — полная очистка данных со сбросом счётчиков `id`
  (с подтверждением);
- **Обновить все вкладки** — перезагрузка данных во всех таблицах.

## Использование драйвера

```python
from db_driver import Database, DatabaseError

try:
    with Database() as db:
        user = db.create("users", {"name": "Ivan", "age": 30})
        adults = db.read("users", where={"age": 30}, order_by=("id", "DESC"))
        one = db.read_one("users", where={"id": user["id"]})
        db.update("users", {"age": 31}, where={"id": user["id"]})
        db.delete("users", where={"id": user["id"]})
except DatabaseError as exc:
    print("Ошибка БД:", exc)
```

Параметры подключения можно передать напрямую, минуя `.env`:

```python
db = Database(host="localhost", dbname="test", user="user", password="12345")
```

### Методы класса `Database`

| Метод | Описание |
|---|---|
| `create(table, data)` | Вставка строки, возвращает её |
| `read(table, columns, where, order_by, limit, offset)` | Выборка строк |
| `read_one(table, columns, where, order_by)` | Одна строка или `None` |
| `update(table, data, where)` | Обновление строк |
| `delete(table, where)` | Удаление строк |
| `fetchall(query, params)` | Произвольный SELECT |
| `fetchone(query, params)` | Первая строка SELECT |
| `execute(query, params)` | Произвольный запрос, число затронутых строк |
| `connect()` / `close()` | Открыть / закрыть соединение |

> Имена таблиц и колонок экранируются, значения передаются параметрами —
> запросы защищены от SQL-инъекций. `update` и `delete` требуют непустой `where`.
